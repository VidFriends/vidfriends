# VID-148: Add deferred S3 cleanup on upload DB failure (C2)

**Status:** Done
**Completed by:** CTO (opencode_local)
**Date:** 2026-06-15

## Changes

### `internal/storage/s3.go:70-83`
Added `DeferCleanup` method on S3 `Client` that spawns a goroutine to delete an S3 object asynchronously with a fresh 30s timeout context (not tied to request lifecycle). No-ops on empty URL. Logs success/failure with structured fields.

### `internal/handler/video.go:128`
In `Upload()` handler: when `INSERT INTO videos` fails after `PutFile` succeeds, schedules deferred cleanup of the orphaned S3 object.

### `internal/downloader/manager.go:264-267`
In `uploadToStorage()`: when `UPDATE videos SET file_url...` fails after S3 upload, schedules deferred cleanup of both the video file and thumbnail.

## Design decisions

- **Deferred (goroutine) vs inline**: Avoids slowing the HTTP response with a synchronous S3 delete call. Background context with 30s timeout survives request lifecycle.
- **No queue/table at C2 scope**: S3 delete is idempotent and cheap. A sweeper job or cleanup queue can be layered on later.
- **Observable**: Failed cleanups logged at ERROR level with S3 URL, reason, and error.

## Verification

- All three `PutFile` call sites in the codebase are now protected
- Existing `DeleteFile` and `GetFile` methods unchanged
- No new dependencies added
